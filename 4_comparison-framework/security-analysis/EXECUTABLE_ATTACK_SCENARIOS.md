# Thrust 5 — Executable Attack Scenarios (per-standard security matrix)

Qualitative security is not enough for a thesis comparison: this thrust turns the
security claims into **executable adversarial transactions**. For each of the
**9 standards** it deploys the real contract on a local Hardhat network, stands
up a legitimate victim identity, then fires a concrete attack (wrong signer,
forged issuer signature, replayed operation, soulbound-token theft, ...) and
records the **real observed outcome** — never a hard-coded verdict. The result is
a per-standard security matrix that sits directly alongside the gas benchmark.

> This is the **execution-driven** half of the security analysis. Its files are
> namespaced `attack_results.*` / `generate_attack_tables.py` so they do not
> collide with any other security artifacts in this directory.

## What is measured

Six attack scenarios, chosen to **parallel the gas benchmark's lifecycle
operation set** (so cost and security read against the same operations):

| Attack (matrix column)          | Threat (STRIDE)              | Benchmark operation it attacks |
| ------------------------------- | ---------------------------- | ------------------------------ |
| `unauthorizedIssuance`          | Spoofing                     | createIdentity                 |
| `unauthorizedAttributeWrite`    | Tampering                    | updateAttribute                |
| `unauthorizedDelegateOrClaim`   | Spoofing / Elevation         | addDelegateOrClaim             |
| `unauthorizedRevocation`        | Denial of Service            | revoke                         |
| `identityHijack`                | Elevation of Privilege       | transferOwnership              |
| `signatureReplay`               | Replay                       | (cross-cutting cryptographic)  |

Each cell of the matrix is one of:

- **DEFENDED** — the malicious transaction **reverted** (access control /
  signature verification / replay guard held).
- **VULNERABLE** — the malicious transaction was **mined** (a real finding).
- **N/A** — the attack does not apply to the standard's identity model
  (e.g. no gated issuance to bypass on a self-sovereign registry; no
  signed/relayed operation to replay).

### Differential rigor (controls)

A revert alone is weak evidence — a call can revert for an unrelated reason.
Every executed cell therefore also runs a **control**: the *same operation
performed by the legitimately authorized party*, which must **succeed**. A cell
is only reported `DEFENDED` when the attacker's call reverts **and** the
authorized call of the identical operation passes (and, where relevant, the
protected state is read back and asserted unchanged). This makes each cell a
true differential test of authorization, not just a revert.

## How to reproduce

Prerequisites: Node.js >= 18 and Python 3 (stdlib only).

```bash
# 1. Execute the attack scenarios (writes results/attack_results.json)
cd 1_blockchain-identity
npm install                                      # first time only
npx hardhat test test/security/securityScenarios.test.js

# 2. Generate the thesis tables (writes results/attack_results.csv and .tex)
cd ../4_comparison-framework/security-analysis
python3 generate_attack_tables.py
```

The LaTeX table requires `\usepackage{booktabs}` and `\usepackage{amssymb}`
(for `\checkmark` / `\times`) and can be `\input{}` directly into the thesis.

## Results snapshot

All **43 applicable** attack cells across the 9 standards are **DEFENDED**; the
remaining cells are honestly marked N/A where the attack does not apply to the
standard's model. Per-standard defended/applicable: ERC-1056 5/5, ERC-721 5/5,
ERC-725 4/4, ERC-735 5/5, ERC-1155 5/5, ERC-4337 5/5, LSP8 4/4, MOBI-VID-V2 5/5,
CVIN-Combined 5/5. See `results/attack_results.csv` for the current matrix and
`results/attack_results.json` for the full evidence (defense mechanism, captured
revert reason, and control result for every cell).

Representative executed attacks (all DEFENDED):

- **ERC-1056 / CVIN-Combined** — attacker `setAttribute`/`changeOwner` on a DID
  it does not own reverts `DIDRegistry: unauthorized` (`onlyOwner(identity,
  actor)`); a consumed `setAttributeSigned` meta-transaction cannot be replayed
  (per-identity nonce folded into the signed hash).
- **ERC-721 / ERC-1155 / MOBI-VID-V2** — role-gated issuance/attribute/revoke
  calls by a role-less attacker revert via OpenZeppelin `AccessControl` /
  `onlyAuthorizedManufacturer` / `onlyAuthorizedIssuer`.
- **ERC-735 / CVIN-Combined** — a claim naming a trusted issuer but signed by a
  rogue key is rejected by on-chain `ecrecover`; an issuer signature bound to
  one vehicle identity cannot be replayed onto an attacker-controlled identity
  (the digest binds the contract/subject address).
- **ERC-4337** — a stranger cannot rotate the signing key nor abuse
  `recoverOwner` (guardian-gated); a previously mined `PackedUserOperation`
  cannot be replayed through the EntryPoint (per-sender sequential nonce).
- **ERC-1155** — a soulbound `BIRTH_CERT` cannot be pulled by an attacker via
  `safeTransferFrom`, while the sanctioned issuer-mediated re-binding succeeds
  (control).
- **LSP8** — a non-owner cannot `transfer` or `revokeVehicle` a token; operator
  delegation/claims are N/A (not implemented in this representative build).

## Honest scope: what is NOT covered

- The attack set targets **on-chain authorization, signature verification and
  replay protection** of the identity-lifecycle operations. It does not model
  off-chain key custody, front-running/MEV, gas-griefing, reentrancy on external
  callees, or economic/consensus-layer attacks.
- `N/A` is used wherever an attack has no analogue in a standard's model, exactly
  as the gas benchmark records unsupported operations as `—` — the matrix never
  fabricates an attack surface to make a standard look worse or better.
- Semantics are the *closest native analogue* per standard (same mapping the gas
  benchmark uses); the per-cell `attack`/`defense` notes in
  `attack_results.json` state precisely what was executed for each standard.
- Outcomes are single-transaction observations on a local Hardhat node; reverts
  are deterministic for a given contract/state. No fuzzing or symbolic execution
  is performed (out of scope for this thrust).
