# Thrust 5 — Security Analysis (executable V2X attack suite)

An **executable** security-comparison of the nine blockchain vehicle-identity
standards implemented in this thesis (ERC-1056, ERC-721, ERC-725, ERC-735,
ERC-1155, ERC-4337, LSP8, MOBI VID V2, CVIN-Combined), plus the off-chain W3C
Verifiable Credential / Presentation (SSI) layer.

Every cell of the resulting matrix is the **observed outcome of an attack that
was actually run** — a malicious transaction whose revert was captured, a piece
of state read back, or a real signature/verifier verdict — not a prose
assertion. Where a property is a *structural absence* (e.g. "no recovery
function exists"), it is marked `reasoned` and argued from the verified contract
source rather than a sent transaction; those cells are the only non-executed
ones, and they are flagged explicitly.

## How to reproduce

Prerequisites: the same toolchain as the gas benchmark — Node ≥ 18 with the
`1_blockchain-identity` dependencies installed (`npm install`), and Python 3
with `web3`, `eth-account`, `cryptography` (already used by the VC layer).

```bash
cd 4_comparison-framework/security-analysis
python3 attack_scenarios.py
```

This (1) runs the off-chain VC/VP attacks in-process, (2) shells out to
`npx hardhat run scripts/security_scenarios.js` in `1_blockchain-identity` to run
the on-chain attacks on a fresh in-process Hardhat network, (3) merges both
layers and the Sybil-cost proxy from `results/gas_benchmark.json`, and (4) writes
`security_matrix.json` + `security_comparison.tex` and prints the matrix.

To run only the on-chain layer:
`cd 1_blockchain-identity && npx hardhat run scripts/security_scenarios.js`.
To rebuild the matrix from an existing on-chain run without re-executing it:
`python3 attack_scenarios.py --offchain-only`.

## Threat model (V2X)

| Category | Attack executed |
|---|---|
| **Impersonation / Forgery** | On-chain: create/mint/`setAttribute`/`addClaim` as a non-owner, and anchor a claim / submit a UserOperation with a **forged issuer/owner signature** — must revert. Off-chain: a VC signed by the wrong key, and a tampered genuine VC — must fail verification. |
| **Replay** | Off-chain: replay a valid Verifiable Presentation with a **stale challenge** — must fail. On-chain: replay a **signed meta-transaction** (ERC-1056 `setAttributeSigned`) / a **UserOperation** (ERC-4337) — a per-identity nonce must reject it. |
| **Identity theft / transfer** | Demonstrate the transfer/theft semantics of each standard: token-transferable (a stolen key moves the whole identity) vs owner-authorised call vs issuer-gated **soulbound**. |
| **Sybil resistance** | Attempt to create N identities as an unprivileged attacker. Gated standards must revert; permissionless ones succeed. The `createIdentity` gas cost is annotated as the Sybil-cost proxy (cheaper creation ⇒ cheaper Sybil). |
| **Key compromise / recovery** | Demonstrate the recovery primitive where one exists (ERC-4337 guardian `recoverOwner`, ERC-1155 issuer re-bind, LSP8 authority revoke+re-mint) and assert permanent-loss where none exists. |
| **Privacy / PII leakage** | After a birth/registration op, **read back on-chain state** and detect whether the VIN appears in plaintext (storage getter and/or event) vs hashed/encrypted. Confirm the canonical DID is `did:ethr` (address-based), not `did:mobi:<VIN>`. |

## Outcome vocabulary

- `DEFENDED` — the attack was blocked by a demonstrated mechanism.
- `PARTIAL` — partially mitigated, conditional, or application-dependent.
- `VULNERABLE` — the attack succeeded, or no mitigation exists.
- `N/A` — the category does not apply to this standard's attack surface.

Each cell also carries `method`: `executed` (a real tx/verification was run and
observed) or `reasoned` (structural absence argued from verified source).

## Per-standard security profile

**ERC-1056 (EthereumDIDRegistry).** All state-changers gated by
`onlyOwner(identity, actor)`; `setAttribute`/`changeOwner` by an attacker revert
`DIDRegistry: unauthorized`. Signed meta-transactions carry a per-identity nonce,
so an identical `setAttributeSigned` replay reverts `invalid signature` — **but
the signed hash omits `block.chainid`, so cross-chain replay is possible**
(documented ERC-1056 limitation). Identity = the address itself; controller is
transferable only via an owner-authorised `changeOwner` (no token/approval
surface). Privacy is strong: no VIN/PII on-chain, only public keys as events.
Weakness: **cheapest, permissionless identity creation** (implicit — every
address is a DID) makes it the weakest on Sybil, and there is **no key
recovery**.

**ERC-721 (CVINVehicleNFT).** Minting gated by `MANUFACTURER_ROLE` (attacker
mint reverts). But the identity **is** a freely transferable NFT: `transferFrom`
and **approved operators** move the whole identity (VIN + history follow the
token) — the widest theft surface. Plaintext VIN is stored in
`tokenIdToVIN`/`vehicleMetadata` and emitted in `VehicleMinted` (full PII
leak). No recovery (admin `deactivateVehicle` cannot reassign ownership).

**ERC-725 (proxy account).** All key/ownership ops require `msg.sender ==
_owner`. Identity is a per-vehicle contract, transferable only by owner call
(`transferOwnership` lacks a zero-address guard — bricking risk). No VIN on-chain
(only key hashes) ⇒ good privacy. Permissionless deployment ⇒ Sybil is
cost-gated only (~529k gas each). No recovery.

**ERC-735 (claim holder).** `addClaim` is `onlyOwner` **and** verifies the
issuer's EIP-191 signature on-chain (with an EIP-2 malleability guard); a forged
issuer signature reverts `invalid issuer signature`. Replay is **partial**: the
signature binds `address(this)+topic+data` (blocking cross-identity replay) but
has no nonce/expiry/chainid, so a same-identity re-anchor is accepted
(idempotent). Plaintext VIN in `string public vin` + `VehicleIdentityCreated`
event. Most expensive to spam (~1.40M gas/identity). No recovery.

**ERC-1155 (soulbound credentials).** Registration/issuance gated by
`ISSUER_ROLE`. **Soulbound**: a holder-initiated `safeTransferFrom` of the birth
certificate reverts — a stolen vehicle key **cannot** move the identity token,
the strongest identity-theft posture of the token standards. Recovery is
**partial/issuer-mediated**: an issuer can `issuerTransferCredential` the birth
cert to a fresh address. Plaintext VIN in `vehicleVIN` + `VehicleRegistered`
event.

**ERC-4337 (smart account + minimal EntryPoint).** Best all-round posture.
Direct calls gated by `onlyOwnerOrEntryPoint`; a UserOperation with a forged
owner signature reverts (`validateUserOp` returns non-zero ⇒ EntryPoint reverts).
**Best replay posture**: the EntryPoint enforces a per-sender nonce **and** binds
`entryPoint address + chainid` in the `userOpHash`. **Only standard with
on-chain key recovery**: `recoverOwner` (guardian-only) installs a fresh signing
key without changing the identity address — demonstrated on-chain (non-guardian
`recoverOwner` reverts). Caveat: single-guardian, instant, no timelock/threshold
⇒ a compromised guardian is itself a takeover vector. Privacy is **partial**: the
attribute store is public and unhashed, so any VIN written there leaks
(app-dependent).

**LSP8 (identifiable asset).** Minting gated by the issuing authority. `tokenId
= keccak256(VIN)` is hashed, but the **plaintext VIN is also stored** under
`DATA_KEY_VIN` and emitted. Token-transferable by the holder (identity moves with
the token; no operator surface, so slightly narrower than ERC-721). Recovery is
partial (authority can revoke + re-mint the same tokenId to a new owner).

**MOBI VID V2.** Birth registration gated by `onlyAuthorizedManufacturer` +
**unique-VIN-hash enforcement** ⇒ strongest Sybil resistance among the registries.
**The only family that avoids plaintext VIN on-chain**: it stores `bytes32
vinHash` + off-chain-encrypted `encryptedVIN`, emits only the hash, and its DID
is `did:ethr:<chainId>:<address>` (no VIN in the DID). Ownership transfer is
owner-authorised and the immutable birth certificate + odometer-stamped ownership
chain preserve provenance. Replay is **partial** with a real finding:
`attestEvent` **stores an attestation signature that is never verified on-chain**
(no `ecrecover`) — a forgery/replay gap gated only by attester role. No key
recovery (inherits ERC-1056 `changeOwner`).

**CVIN-Combined (thesis hybrid, ERC-1056 + ERC-735).** `onlyIdentityOwner` on the
event side; `addClaim` verifies a raw-digest issuer signature (a forged claim
reverts). Replay is **partial** (claim binds `address(this)+identity+topic+data`
but no nonce/chainid, and no EIP-2 malleability guard). Base identities are
permissionless and near-free (~52k) ⇒ weak Sybil, though safety-critical *claims*
still require a trusted issuer signature. Privacy is **partial**: ERC-1056
attributes are event-only (not stored), but ERC-735 claim `data` is stored and
returned by `getClaim` — unhashed, so a VIN placed there leaks (app-dependent).
No key recovery.

**W3C VC/VP (off-chain SSI layer).** Forged/tampered credentials fail signature
recovery against the issuer DID; a presentation replayed with a stale challenge
fails; a stolen credential presented by a non-holder (same holder DID string,
wrong key) fails holder-binding. Selective disclosure hides undisclosed claims,
and identities use `did:ethr`. Sybil/recovery are **partial**: issuer trust is
governance-gated at a registry (not at DID creation), and key recovery is
delegated to the on-chain layer (the VC layer offers credential *revocation* but
not key recovery).

## Cross-cutting findings

1. **Plaintext-VIN leakage is the norm, not the exception.** ERC-721, ERC-735,
   ERC-1155 and LSP8 all write the raw VIN into public storage and/or events for
   the birth/registration op (read back and confirmed on-chain). **MOBI VID V2 is
   the only family that hashes + encrypts the VIN.** ERC-1056/ERC-725 carry no
   VIN at all; ERC-4337/CVIN-Combined leak only if the application stores a VIN
   in the (unhashed) attribute/claim payload.
2. **`did:mobi:<VIN>` is a privacy anti-pattern.** The DID resolver
   (`2_w3c-ssi-layer/did-resolution/did_resolver.py`) *defines* a
   `did:mobi:<VIN>` method that would embed the plaintext VIN in the DID string
   (and in `alsoKnownAs: vin:<VIN>`). The canonical stack and the on-chain MOBI
   registry instead anchor identity to `did:ethr:<chainId>:<address>` (confirmed
   via `getVehicleDID`), avoiding the leak — but the resolver's `did:mobi` method
   remains a footgun and is flagged as such.
3. **Replay protection exists only where meta-transactions do.** Correct
   nonce-based replay protection is present in ERC-1056's signed variants (no
   chainid) and ERC-4337's EntryPoint (nonce **+** chainid). ERC-735 and
   CVIN-Combined bind the claim to context but lack a nonce (idempotent
   re-anchor). The pure token standards have no in-contract signature to replay.
4. **Recovery is the sharpest differentiator.** ERC-4337 is the only standard
   with genuine on-chain key recovery (guardian). ERC-1155/LSP8 offer
   issuer/authority-mediated re-binding. Everything else: a compromised owner key
   is permanent loss.
5. **Sybil resistance tracks issuer-gating, not just gas.** The cheapest
   creators (ERC-1056 ~52k, CVIN-Combined ~52k, both permissionless and implicit)
   are the weakest; issuer-gated MOBI/ERC-1155/ERC-721/LSP8 raise the bar to an
   authorisation, not merely gas.

## Honest limitations (what was executed vs reasoned)

- **Executed** (real tx + observed outcome): every `impersonation` cell; the
  `replay` cells for ERC-1056, ERC-4337, ERC-735, CVIN-Combined and all
  off-chain scenarios; every `identity_theft` cell (transfer/soulbound
  demonstrations); every `sybil` cell (gating reverts / successful mass creation);
  the ERC-4337, ERC-1155 and LSP8 `recovery` cells; and every `privacy` cell
  (state read back on-chain).
- **Reasoned** (structural absence, not a sent tx, marked `*`/`reasoned`): the
  `recovery = Vulnerable` cells for standards with **no** recovery function
  (ERC-1056, ERC-721, ERC-725, ERC-735, MOBI, CVIN-Combined) — we assert the
  primitive is absent from the verified source rather than "failing to recover";
  the `replay = N/A` cells for the pure token standards (ERC-721, ERC-725,
  ERC-1155, LSP8), which have no in-contract signed message to replay (protection
  is the protocol-level Ethereum tx nonce); and MOBI's `replay = Partial`
  attestation-verification gap (identified from source; the identity path itself
  has nothing to replay).
- **Harness caveats.** The ERC-4337 EntryPoint is the thesis's minimal research
  harness (no bundler mempool, paymaster, or gas accounting), so replay/recovery
  are evaluated on its validation logic, not a production v0.7 EntryPoint.
  `encryptedVIN` privacy for MOBI depends on off-chain encryption the contract
  does not verify — we confirm only that no plaintext VIN is written on-chain,
  not the strength of the ciphertext. `looksLikeVIN` uses an ISO-3779 pattern
  match to detect plaintext; a VIN deliberately obfuscated by an application
  would not be caught (but none of the audited contracts do so).
- **Scope.** This suite targets the identity/registration attack surface and the
  V2X threat categories above. It is not a full formal audit: reentrancy, gas-
  griefing, integer-overflow (beyond the known MOBI validity-overflow already
  worked around in the gas benchmark), and economic/MEV attacks are out of scope.
